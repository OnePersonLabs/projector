# Model-native runtime

`§model-native-runtime` · A longer-horizon possibility, not a prerequisite for Projector.

## Hypothesis

If a persistent system conception can support reliable project-specific judgment, some application behavior might eventually be executed through model-mediated interpretation rather than permanently expressed as conventional source code.

This is a research branch. The supplied material does not establish a working, reliable replacement for ordinary software execution, and the rest of Projector does not depend on it succeeding.

## Fluid and crystallized behavior

Open-ended interpretation or adaptation could remain model-mediated where variability is useful. Stable, repeated, latency-sensitive, protocol-critical, security-sensitive, or exactly checkable behavior should be candidates for deterministic implementation.

“Crystallization” means turning a demonstrated behavior into a stable executable artifact when doing so improves reliability or economics. It does not mean that every learned behavior can be translated without loss, or that a model should improvise a real-time audio loop.

The same conception can potentially support multiple materializations. Different implementations may satisfy the same observable contracts without being textually identical.

## Reconstruction is not byte recovery

A useful reconstruction experiment checks accepted behavior, architecture, responsibilities, and meaningful constraints. Exact byte reproduction is appropriate only for artifacts whose contract requires deterministic generation.

A reconstruction success should not be allowed to come from hidden copies in tool caches, retrieval stores, or prior context. A failure should be examined for missing evidence, representation limits, or an overly strong reconstruction criterion.

## Why keep this branch

It tests the deepest version of the distinction between meaning and materialization. It may reveal which aspects of project understanding can be amortized and which must remain explicit.

It should not delay a practical context compiler, evidence-linked explorer, or mechanical materialization pipeline. Those can provide value without replacing the software runtime.

## Decision to defer

Do not make a model-native runtime part of the minimum implementation. Reopen this branch only after narrower experiments demonstrate reliable project-specific judgment, controlled updates, useful reconstruction, and a plausible end-to-end cost advantage.
