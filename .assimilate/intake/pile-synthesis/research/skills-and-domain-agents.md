# Skills and domain agents

**Evidence status:** supplied research adaptation, an engineering guide, and practitioner accounts. Distinguish measured results in a specific study from predictions and private deployment anecdotes.

## What a skill changes

A skill packages instructions and potentially references, examples, or scripts. It changes the working environment and procedure of a receiving agent. It does not by itself change the model's parameters or establish that the model will execute the procedure correctly.

Progressive disclosure can keep a short trigger description separate from deeper instructions and executable resources. The trigger itself is part of the behavior to evaluate: invoking the wrong skill or failing to invoke a necessary one can defeat an otherwise good procedure.

## Trace2Skill's useful mechanism

The supplied adaptation of Trace2Skill version 1 describes collecting labeled task trajectories, independently analyzing local failures or successes, and consolidating proposed lessons into a coherent skill.

“Deepening” begins with an existing skill. “Creation” develops a skill from a different initialization. These conditions must not be compared as though their baselines were identical.

The useful abstraction is **experience → local lesson → independently assessed merge → evaluated procedure**. It avoids assuming that a generic instruction draft is sufficient or that sequentially appending fixes produces a coherent skill.

## Transfer is empirical, not a model-size law

The retained results show a human-written skill helping one model while hurting another. On the reported Verified measure, the 122B user moves from 27.67% without the skill to 48.33% with it; the 35B user moves from 19.00% to 9.67%.

The same material reports beneficial transfer in both directions. For example, an error-analysis deepening condition authored by the smaller model improves the larger user's Verified result from 48.33% to 65.00%. A larger-authored deepening condition improves the smaller user from 9.67% to 36.67%.

These comparisons show that transfer can work. They do not identify one universal cause for success or regression. The receiving environment, initialization, task distribution, evidence used in refinement, and evaluation measure all matter.

Baseline values are absolute percentages. Evolved rows in the original study include percentage-point changes from their relevant initializations. Confusing the two creates misleading results.

Success-only and combined analyses can also regress. More evidence, a larger author, or a longer skill is not automatically better. The source adaptation specifically corrects claims that small models inherently cannot produce useful transferable guidance.

## Evaluate the receiving behavior

Test successful invocation, near-miss non-invocation, prerequisites, allowed side effects, output conventions, task completion, and efficiency. Use actual traces and artifacts rather than a model's claim that it followed the skill.

A skill may contain a deterministic helper precisely because repeated exact work should not be improvised. Test that helper independently. A skill generated by a creator tool is still a candidate artifact, not proof that it has passed all relevant evaluations.

## Domain-specific agents

A domain agent can expose a small, well-defined capability with restricted tools and only the context necessary for its task. This can reduce duplicated context and make less expensive models useful for qualified work.

The domain-agent transcript defines an agent as deterministic software using nondeterministic model outputs toward an objective. That definition is a useful engineering stance, not the only possible taxonomy.

Integration, durable execution, validation, and stopping conditions can justify a specialized harness. They can also make a custom agent costly to maintain. Reuse an existing capable execution environment before rebuilding its loop for a narrow integration.

The transcript reports large token-efficiency gains in a private ecosystem and predicts wider adoption. Those are practitioner claims without a supplied controlled benchmark. They do not establish savings for a Luna/Astra setup or prove that every domain needs a separate process.

## Projector's adaptation

Persist semantic identity and useful procedures, not a permanent personified agent for every concept. Activate bounded computation when a question appears. Compile recurring reliable work into cheaper tools, views, fixtures, or skills.

The canonical design is [cognitive compilation](../concepts/cognitive-compilation.md). The version-specific research pointer is Trace2Skill, `arxiv:2603.25158v1`, March 26, 2026; the source adaptation explicitly uses version 1 rather than mixing later revisions.
