# 2. The right mathematical property may be **equivariance**, not merely invariance

This hit me pretty hard while reading it.

We've repeatedly said:

> representation changes should preserve S.

But that's subtly wrong.

Some transformations should leave S unchanged:

```text
rename class
reformat code
English → Japanese explanation
```

Those want **invariance**:

\[
Z(gx) \approx Z(x)
\]

But other valid transformations should cause a corresponding structured change.

Swap an audio backend, split a subsystem, move a boundary, add offline capability.

The conception doesn't remain numerically identical. It changes **in a lawful way**:

\[
\boxed{
Z(gx) \approx \rho(g)Z(x)
}
\]

That's equivariance: when the world transforms, the representation transforms correspondingly.

This distinction is well established in representation learning, where invariance is actually a special case of equivariance. citeturn819282academia2turn819282academia3

For us:

- **surface nuisance transformation** → invariant
- **meaning-preserving structural transformation** → equivariant
- **distortion** → should violate learned transformation law
- **authorized conceptual evolution** → updates the law itself

That is a much more precise learning target than “the embedding should stay similar.”

And it maps beautifully onto your action-pattern notion.
