## Material integrity and interpretation findings

The OpenAI donor is not merely short: its Jalapeño text and August date come from the real article's related-content area. The separately recovered article is Ryan Lopopolo's February 11, 2026 engineering account. Its practices are useful experience evidence, and its long-term coherence remains unestablished. [Official article](https://openai.com/index/harness-engineering/)

CodeThread's headline 13.1 difference is percentage points on a shared-instance comparison. It is not a relative maintainability loss or the maximum over every appendix cohort. Some primary appendix counts/percentages disagree; the ingest also drops important tables. Its attribution of downstream failure to drift is a judge's assessment, without an intervention establishing cause. These issues limit exact-effect reliance; they do not invalidate the idea of a matched later-task experiment. [Paper v1](https://arxiv.org/html/2606.21804v1), [pinned author repository](https://github.com/shaswatpatel123/CodeThread/tree/158f6abaadcf717f3175a8f402be7da4e8d48c76)

SlopCodeBench's 14.8% headline is a strict checkpoint solve rate, not the fraction of all tests passed. Its own sensitivity analysis reports essentially no association between its erosion measure and subsequent checkpoint passing. Prompt interventions bundle several changes, contain model-specific exceptions, and do not test Projector. One supplied multi-checkpoint example also conflicts with its earlier sorting contract. Evaluation must adjudicate the specification before blaming an implementation. [Paper v2](https://arxiv.org/html/2603.24755v2), [pinned source](https://github.com/SprocketLab/slop-code-bench/tree/06b5c0687d4c05ee502e9696a4d0c22fc1eec5e0)

Sophontic's inspected public claim compares model parameter size, while required model/evaluation artifacts were listed as forthcoming. It does not establish a latency, energy or complete-cost multiplier. Epiplexity research concerns bounded structural information and explicitly does not guarantee any particular downstream generalization. Neither supplies a causal link to Projector's software or work graphs. [Model page](https://sophontic.ai/models/), [evaluation page](https://sophontic.ai/evals/), [epiplexity paper v2](https://arxiv.org/html/2601.03220v2)

Some named technologies in the donors are real: for example, eve has an official Vercel announcement. Rejecting unsupported economics does not justify dismissing every surprising name as fabricated. Existing host subagents, tools and durable runtimes are alternatives to duplicating that machinery; their existence does not establish a fit with Projector's state and authority model. [Vercel announcement](https://vercel.com/blog/introducing-eve), [Claude subagent documentation](https://code.claude.com/docs/en/sub-agents)

These are concrete source and reasoning problems, not claims to know which passages the user intentionally planted. The design does not depend on accusing a source of deception.

## Recipient evidence and actual checks

All eight package responsibilities, CLI/plugin composition, canonical state, historical module boundaries and relevant tests were inspected. The detailed public reachability ledger is [W4](research/W4-recipient.md). Existing functionality is distinguished from internal kernels and unavailable public handlers. The architecture synthesis specifically accounted for the one-packet lifecycle, weaker host wrapper, sandbox/network boundary, immutable capture identity, broad validator read cone, and non-reconstructible runtime evidence.

Executed in this campaign: Projector status/context/reconciliation reads, source inventories/hashes, primary source verification, and a built MCP `tools/list` experiment. The first commands and W4's MCP experiment used system Node 22.23.2 and do not certify the Node 24 target. A later focused saved-context command used installed Node 24.20.0 successfully. Exact context IDs and final reconciliation are in [STATE.md](STATE.md) and the receipts directory.

The source-built MCP experiment returned five ordinary read handlers; the plugin adds workspace binding separately and authenticated representation can add other reads. A declared larger catalog is not the callable API. No paid-model run, donor benchmark reproduction, application experiment, full code test suite or economic comparison was performed. Existing historical test counts were not claimed as new verification.

The unapplied historical-spec patches and copied-tree checks are recorded separately in [spec verification](receipts/spec-verification.md). Independent review and its disposition are retained in [design review](research/W6-review.md). Those checks validate this design package, not product execution.

## Reuse, attribution and unresolved frontier

No donor implementation, prompts or article bodies are imported. The design is original synthesis with source-linked paraphrases; supplied ingests are preserved unchanged. Primary repositories are pinned as evidence, not vendored dependencies. Original video/transcript attribution and license are unresolved for some secondary sources. Any later copying of code, prompts, datasets or media needs a specific license check at the pinned revision; this uncertainty does not block using the independently described engineering mechanism.

The first real scenario and collection design are now selected in [APPLICATION-PILOT.md](APPLICATION-PILOT.md), using read-only inspection of the clean Psychord checkout at its pinned revision. Its source inventory is separate from the original 11 donors. Remaining implementation questions are bounded and explicit: validate the selected oracle and demonstrate the chosen platform/resource capabilities; finalize minimal core/runtime contracts against actual integration; observe contribution overhead; run the proposed longitudinal trial under a declared budget. None is reported as experimentally verified. Sophontic release artifacts, EILT lineage, benchmark cohort reconciliation, universal routing economics and exhaustive predecessor research remain outside the necessary implementation dependency chain.
