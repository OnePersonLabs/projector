# Integrated implementation order

These are future execution steps after acceptance of the design, not a new task-status authority. Exact task definitions and acceptance evidence are in P1--P4. Do not revive historical delivery task numbering or turn this file into a runtime workflow store.

| Stage | Tasks | Dependency and result |
|---|---|---|
| Establish meaning and evaluation boundary | P1.1, P2.1, P4.1 | Accept only chosen meaning/architecture and freeze the evaluation protocol. Existing obligations and actual pilot are retained. Live trials do not begin yet. |
| Prove the risky collection boundary | P1.2--P1.5 | Implement portable contracts, selected optional container profile, actual triad adapter and evidence admission. Wrong-run/controller/host-escape controls must pass before strong evidence is advertised. |
| Connect real evidence to public behavior | P1.6--P1.8 | Make context/coverage and concrete controlled validation consume the observation. Exercise the actual application, not only a protocol fixture. Release this useful slice at its proven scope. |
| Join and resume checked work | P2.2--P2.7 | Bind full envelopes into proposal/plan identity, freeze attachments, expose continuation and repair weak host assurance. Parallelize implementation only across settled non-overlapping interfaces; accepted mutation stays serial. |
| Close an actual correction loop | P3.1--P3.4, P3.6--P3.7 | Use one real failure from existing validators or P1/P2. Classify honest evidence and correct its owner. P3.5 and architectural consequences are conditional on justified reusable enforcement. |
| Exercise subsequent change | P4.2--P4.7 | Drive matched accumulated-state changes through actual public paths. Separate functional acceptance, later regressions and all observed costs. Expand research only for decision-relevant uncertainty. |

P2 contract/admission implementation and P4's model-free trajectory driver can proceed alongside P1 after shared core interfaces are settled. P3 can begin with an existing reproduced validator failure; it does not require waiting for every adapter. Do not parallelize shared schema/registry/lifecycle edits without explicit ownership and integration.

For each coherent code slice: build with Node 24, run relevant realistic tests and public acceptance, run the repository's required verification/boundary/schema checks, reconcile the retained context, and review the integrated diff. Do not repeat a full suite at every agent handoff or substitute passing self-authored tests for the independent survival case.

At handoff report specified intent, implemented path, exercised behavior and measured advantage separately. Unsupported capabilities and preserved future obligations remain visible. Comparative trials are opt-in/budgeted and do not block a useful release whose applicable behavioral and safety requirements passed.
