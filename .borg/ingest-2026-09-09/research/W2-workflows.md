## Decision-ready assessment

Retain bounded delegation, explicit dependency and state ownership, review with separately sourced evidence, small recoverable work increments, and executable restart recipes. Adapt them into existing Projector concepts and concrete host integrations. Do not adopt a universal agent graph, a second feature ledger, a recursively autonomous domain-agent platform, or a mandatory full review stack for every node. None of the donors demonstrates that those broader constructions outperform a strong ordinary agent with selective tools, relevant context, and the same validators.

The largest recipient distinction is between an implemented library contract and a supported workflow. Projector has a multi-packet compiler and execution coordinator, but its public repository-change lifecycle currently accepts exactly one compiled packet. Its structured Codex model provider exists without a production caller in `packages/`. Its public host runner has an authenticated-session route, but that route is substantially weaker than the repository-change executor. These are separate integration boundaries, not a single working orchestration engine.

## Primary-source verification and corrections

Checked on 2026-09-10. Documentation describes current capabilities; it is not proof of installation or successful execution in this workspace.

1. Anthropic's initializer/coder account, limited web-app setting, browser verification, and unresolved multi-agent comparison are confirmed by the [original harness article](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents). Its reported improvement does not establish Projector advantage. The donor's claim that all agents automatically verify is also contradicted by this report's observed premature completion without adequate testing.
2. [Claude Code skills documentation](https://code.claude.com/docs/en/skills) confirms bundled verification, selective automatic invocation, project-specific launch recipes, and Skill Creator's with/without-skill evaluation loop. Bodies load when used, while advertised skill metadata still costs context. Thus counting installed Markdown files is not the same as measuring loaded context. A generated skill is not inherently validated merely because a creator generated it. Current documentation also permits replacing a bundled verify recipe with a project skill and controlling visibility; the donor's blanket inability to affect preinstalled skills is too broad.
3. [`claude -p` documentation](https://code.claude.com/docs/en/headless) confirms noninteractive invocation, structured output and explicit continuation. `-p` alone is not a backgrounding primitive or assurance of clean context: ordinary project/user hooks, skills and configuration can load. Bare mode changes discovery and authentication behavior. A second process therefore needs an explicit input/configuration/evidence contract before its output can count as independent review.
4. [Claude Code subagent documentation](https://code.claude.com/docs/en/sub-agents) confirms separate context, optional tool restrictions and worktree isolation, and bounded nested delegation. It also explains inherited project rules and task summaries. These existing mechanisms are a serious alternative to a custom domain-agent runtime. A fresh context still shares model biases, source material and the delegator's selection; it is not unbiased.
5. [AutoGen GraphFlow documentation](https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/graph-flow.html) explicitly supports sequential, parallel, conditional and looping behavior and labels GraphFlow experimental. A loop is a graph pattern; parallelism is a scheduling choice. There is no architectural transition that makes loops obsolete.
6. [LangGraph persistence documentation](https://docs.langchain.com/oss/python/langgraph/persistence) separates per-thread checkpoints from cross-thread stores and warns that in-memory checkpoints disappear on restart. A framework name does not supply durable state automatically in every configuration. Nor does persistence itself define acceptance, compensation or ownership of Projector canonical state.
7. [Chrome's Headless Shell documentation](https://developer.chrome.com/docs/automation-and-testing/headless-chrome-shell) states a performance/authenticity tradeoff and favors real Chrome Headless where fidelity or full browser functionality is needed. The donor's blanket faster-substitute recommendation is unsuitable as Projector policy. Psychord input/audio behavior especially requires measuring the actual chosen browser path.
8. [Vercel's eve announcement](https://vercel.com/blog/introducing-eve), dated 2026-06-17, confirms a real framework with durable sessions, sandboxing, approvals, subagents and evals. [AI SDK ToolLoopAgent](https://ai-sdk.dev/docs/reference/ai-sdk-core/tool-loop-agent) provides reusable model/tool loops. These are current alternatives to hand-built runtime plumbing; selecting either for Projector would still need host portability, state-binding, effect and recovery comparisons. A cloud framework's production claim cannot substitute for this comparison.
9. [MCP server documentation](https://modelcontextprotocol.io/docs/2026-07-28/learn/server-concepts) defines tools, resources and prompts. The donor's historical client-support screenshot may describe its observation then; it does not establish that MCP is intrinsically tools-only or cannot carry domain-specific interfaces. Protocol capability and particular client registration are different evidence.
10. [Standard Agents' supplied domain](https://standardagents.ai/) redirected to Standard Agent Builder and yielded no extractable benchmark. Targeted primary-source search did not produce a reproducible basis for the donor's 80% efficiency, 137x per-task price ratio, 29% IQ-adjusted inflation or 76% nominal inflation. Preserve these as unverified donor assertions. Model identities, task mix, caching, retries, quality threshold, denominators and prices are missing. No candidate design depends on them.

The transcript's assertions about Anthropic's internal four-skill sequence, the Cursor-attributed Thermonuclear review, universal browser testing defaults, and SerpApi's advertised service figures were not independently established. They are unnecessary to the surviving mechanisms and carry no acceptance authority.

### Cross-cutting rejection reasons

- **Graphs versus loops:** reject the dichotomy. Control/data dependencies, cycle semantics and scheduling determine execution. A loop can parallelize independent work; a graph can be entirely sequential. A node may be deterministic validation or a human decision, not necessarily an LLM.
- **Every node runs every reviewer:** reject the unbounded default. Fan-out multiplied by review fan-out rapidly duplicates source retrieval and correlated findings. Checks belong at the state boundary that can invalidate their assumptions, with risk and measured utility determining depth.
- **Every agent needs shell access:** reject the universal claim. Capability minimization can mean no filesystem, no shell and no credentials. A sandboxed process does not alone guarantee no exfiltration, correct tenant access or safe network effects.
- **English-only handoffs:** keep readable objectives and reasons, but require typed identity, evidence references, error status, cancellation, idempotency and authority bindings where machines must enforce them. This is compatible with Projector's accepted engineering-English requirement; it is not a second competing specification.
- **Pass flags as acceptance:** reject mutable flags as authority. They may be a derived display of current scenario evidence. The initializer must not silently expand user intent into hundreds of accepted requirements.
- **Permanent green state:** a receipt describes a particular validated state. A future session must distinguish historical success, currentness and current conformance. Cached success is not eternal feature completion.
- **Git/progress as universal recovery:** retain provenance and orientation, but arbitrary reset/commit operations do not replace journaled recovery or shared-workspace ownership. An existing dirty tree can be legitimate; restart must not erase it to satisfy a slogan about cleanliness.

## Differentiated conflict cases for the integrated design

1. **Disjoint files, shared meaning.** Two workers edit UI labels and an API schema in different directories for one accepted concept. Path separation suggests parallelism; semantic coupling requires a common contract/version. Candidate behavior: parallel read-only investigation, one agreed integration boundary, then effects under existing authority. Test that syntactically valid but incompatible outputs do not merge as success.
2. **Independent review, correlated oracle.** Author and new Opus reviewer both use the same generated tests that misunderstood a negated requirement. Candidate behavior: evidence source lineage exposes correlation; a canonical forbidden-outcome scenario supplies a separate oracle. Merely changing model/session must not satisfy independence.
3. **Intentional implementation versus stylistic finding.** Smaller reviewer calls an alternate conforming implementation a defect because it differs from a familiar pattern. Candidate behavior: compare to the applicable predicate and reasons, not pattern similarity. The existing `scenario:alternate-conforming-code` already protects this distinction.
4. **Crash after effects, before progress note.** Browser verification passed and a governed transaction committed, but the session dies before publishing a receipt. Candidate behavior: authenticate the prepared-success checkpoint and finalize it; do not rerun effects just because a text note says unfinished. Public lifecycle already contains this recovery mechanism; expose it rather than rebuild it.
5. **Stale environment with fresh prose.** Resume notes say the app runs at port 3000, but another worktree owns that port. Candidate behavior: setup verifies instance identity/readiness and binds the scenario observation to the correct state. A visually plausible screenshot from the old instance must fail evidence binding.
6. **Portable agent, unportable authority.** A Salesforce helper copied to another tenant has the same prompt but different credentials and write permissions. Candidate behavior: packaging transfers code/contracts; deployment rebinds authority and validates tenant/tool scope. Prompt portability cannot transfer a previous approval.
7. **Budget exhaustion before a barrier.** Three research lanes finish; one times out; the merge has enough material to sound convincing. Candidate behavior: required evidence remains unavailable, optional evidence is explicitly omitted, and partial findings are durable. Do not synthesize a fabricated all-lanes-success result or retry indefinitely.
8. **Cyclic repair without convergence proof.** A generator changes a schema, a consumer repair changes assumptions and the generator changes it back. Candidate behavior: cycles need bounded staging, explicit fixed-point observable and non-convergence outcome. The current coordinator's early rejection is more truthful than its unreachable convergence loop would suggest.
9. **Runtime evidence asks for a broader effect.** A browser scenario needs audio access or an external service that the selected sandbox cannot expose. Candidate behavior: report the unsupported observation and select a concrete authorized adapter; do not loosen the general execution boundary or promote missing evidence to passing status.

## Remaining evidence and limits

- No new live execution or economic trial occurred in this packet. Public currentness/recovery source and tests were inspected. Existing campaign receipts may establish exercised behavior for their exact version/scenario, not the unimplemented graph/provider/runtime routes.
- Need a public-path run of the actual installed model provider with no fake feature inventory, if that provider is selected; a creator export and test fixture are insufficient. Need measured startup/tool support and output-contract behavior across claimed host versions.

- Need a future scheduling decision only if the single-packet lifecycle becomes a measured bottleneck. Concurrency brings shared meaning, writer leases, conflict handling, cancellation and durable partial results; none follows automatically from adding graph edges.
- Caller audit did not inspect every external script or downstream consumer. Claims are explicitly scoped to the repository's `packages/` production TypeScript. W4 owns broader public/plugin reconciliation.

This artifact retains actionable mechanisms, disconfirming cases and source limits. Accepted meaning remains in typed `.projector/` records; campaign notes and donor rhetoric do not acquire authority by being detailed.
