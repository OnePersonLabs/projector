# Projector development

This file governs development of Projector itself. Put instructions for every repository using the plugin in `plugins/projector-v3/AGENTS.md`, workflow-specific guidance in the owning skill, and deterministic lifecycle actions in plugin hooks. Keep repository implementation conventions here; executable contract and schema authority belongs in `packages/core/`.

Treat an observation timeout as a resource-budget signal, not a correctness requirement or an optimization target in itself. Inspect the failed stage and enough evidence to distinguish repeated or avoidable work from legitimate repository cost. Fix a clear recurring inefficiency when its expected benefit justifies implementation and verification time. Do not prolong delivery with repeated profiling or speculative tuning merely to meet the default deadline. When the remaining work needs more time, use an explicit bounded timeout override and record the reason. Preserve repository coverage, currentness and authority checks, unknown results, cancellation, and recovery guarantees. Never turn an incomplete observation into success or rerun a possibly committed mutation without inspecting its actual lifecycle state.
