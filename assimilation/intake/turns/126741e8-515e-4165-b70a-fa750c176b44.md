### My Codex cheat sheet

| Setting | Intuitive meaning | Use it for |
|---|---|---|
| **5.6 Sol High** | “Good senior engineer, get this done.” | Normal implementation, tests, known patterns, contained refactors |

## The two-question decision tree

### 1. **Does Codex know *what kind of solution* it's looking for?**

If **yes → Sol**.

If **no / that's part of the task → GPT-6**.

Examples:

> “Implement this already-specified API endpoint.”  
> → **Sol High**

> “Why does this architecture keep devolving into duplicated abstractions, and what structural change actually fixes it?”  
> → **GPT-6 High**

That is the big axis.

---

### 2. **How dangerous is a locally-plausible answer?**

If a plausible first solution is probably fine:

> **High**

If the problem contains hidden interactions where something can look correct for 20 minutes before detonating three layers away:

> **XHigh**

So:

**Sol High**  
`known solution space × ordinary hidden complexity`

**Sol XHigh**  
`known solution space × lots of hidden complexity`

**GPT-6 High**  
`unknown solution space × ordinary/deep exploration`

**GPT-6 XHigh**  
`unknown solution space × lots of hidden complexity`

That 2×2 is probably all you need.

## For *your* work specifically

I would **not** default everything to XHigh. OpenAI explicitly warns that higher reasoning uses more allowance and **doesn't always improve the result**. citeturn234277search5

I'd run roughly:

**Psychord**
- Add a clearly specified component → **Sol High**
- Implement a known architecture across several packages → **Sol XHigh**
- Determine the architecture / boundaries / invariant system → **GPT-6 High**
- “Audit this whole thing for architectural entropy and derive the structural fix without reducing the premise” → **GPT-6 XHigh**

**Projector / agent harness work**
- Implement an already-designed rule → **Sol High**
- Trace spec-loading / precedence weirdness → **Sol XHigh**
- Invent a robust divergence/eval architecture → **GPT-6 High**
- Reconcile spec-driven + eval-driven + agent-loop architecture across the entire system → **GPT-6 XHigh**

**Debugging**
- Stack trace points at something → **Sol High**
- “Something is subtly wrong” → **GPT-6 High**
- “Three agents have fixed this and every fix creates another impossible symptom” → **GPT-6 XHigh**, summon the orbital debugger.

### One especially useful distinction

Think:

> **Sol: execute within the frame.**  
> **GPT-6: inspect/change the frame.**

And:

> **High: solve it.**  
> **XHigh: distrust the obvious solution.**

That gives you four memorable combinations:

**Sol High:** execute  
**Sol XHigh:** scrutinize  
**GPT-6 High:** discover  
**GPT-6 XHigh:** interrogate reality

For your kind of development, I’d probably make **Sol High the mundane default and GPT-6 High the “important thinking” default**. Then treat both XHigh modes as deliberate escalation, rather than leaving XHigh on all the time.
