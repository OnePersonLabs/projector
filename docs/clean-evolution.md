# Hosted clean-evolution evidence

These trials use the installed Projector **4.0.0** runtime on the qualified
Windows profile. Native Codex participants inherit the parent task's configured
model; no model override, external inference API or separate paid-credit call
is used. Each participant receives only its assigned trial, legitimate
requirements, editing boundaries and a ten-minute ceiling. Oracle source and
assertions remain outside participant context.

The initial campaign consists of three evolved/direct pairs. The affected
evolved preview case is repeated after a concrete fixture correction: its first
version already contained the strategy at baseline, proving removal but not
addition followed by removal. The corrected case begins with an ordinary
runtime, introduces the functional strategy and retained history, executes
intermediate evidence, and then withdraws the strategy. The initial case is
preserved as diagnostic evidence and is excluded from final pair acceptance.
The original direct preview candidate also failed a concrete nested-identity
mutation probe: shallow copies allowed one subscriber and the caller to change
retained data and another subscriber's record. The held-out probe and authored
good control were strengthened, and only that affected direct case was repeated.
Both original cases remain diagnostic evidence, excluded from final acceptance.
There were **eight participant runs: six initial runs and two targeted repairs**.
There are no unrelated repeats or expanded benchmark scenarios.

## Procedure and independent review

`evaluation/index.ts` creates ordinary JS ESM repositories with nested OpenSpec
requirements/designs. Their adapter loads the installed change service, invokes
prepare/plan/apply, and executes real verification commands. Evolved runs preserve
an intermediate Git checkpoint and executed evidence before revising the same
active target. Target refinements add precise realization bindings for actual
supporting artifacts; requirement meaning remains fixed.

Participants stop before independent review and finish. The parent agent, which
did not implement their candidates, examines the exact target, baseline diff,
source, current ownership, retired contributions, executed checks and credible
simpler alternatives. It runs the held-out evaluator and records the actual
review with the current basis. Projector executes the independent verification
again with the complete changed-artifact scope before publication. Review records
are attributed observations, not cryptographic proof of independence.

Finish checks are substantive. Missing evidence for removed/supporting files
blocked the first preview publication until independent checks covered them.
Unchecked implementation tasks blocked shared-direct publication; the parent
marked the two actually verified tasks complete, refreshed their basis and
reran evidence. Neither result was bypassed with a fabricated pass.

The published candidates are archived by the real pinned OpenSpec adapter. A
second Projector finish must return the same publication and leave a clean
candidate worktree. Every trial's accepted `main` remains at its initial commit.
Application checks also execute with Projector environment variables removed;
application source does not import the tool runtime.

The corrected evolved preview reached the archived phase before Git rejected a
long Windows archive filename during staging. Projector now passes
`core.longPaths=true` to its internal Git invocations on Windows, preserving user
Git configuration. The installed runtime resumed the same sealed archive and
published it without discarding the candidate or rebuilding its implementation.
The deterministic recovery regression also covers an archive filename longer
than 260 characters. Git's separate internal worktree metadata root-length limit
still applies; a root rejected with `$GIT_DIR too big` must be shortened.

## Final results

All three final pairs pass the strengthened evaluator after publication, with
matching observed behavior. Every candidate has executed evidence, an actual
independent review, a verified archive, unchanged accepted `main`, a clean
candidate worktree and a repeated-finish no-op. Application checks pass without
Projector environment variables.

The [machine-readable evidence](evidence/clean-evolution.json) records full
publication, baseline and target hashes, intermediate checkpoints, review
reasons and alternatives, executed evidence hashes and scopes, final oracle
traces, excluded diagnostic cases and the local artifact location. These are
trial-repository commits, separate from the Projector implementation branch.

## What is compared

The held-out checks exercise monotonic playback provenance, detached records
including nested identity mutation across callers and subscribers,
independently replaceable evidence, ordered late replay, later delivery,
unsubscribe, actual consumer/source ownership, absent retired routes and absent
unnecessary dependencies. Reconciliation must preserve unchanged content and
modification time. A new legitimate consumer is then introduced to prove that
changed inputs invalidate a previously settled result; the probe restores its
input bytes afterward.

The oracle was qualified separately against authored good controls and five
seeded failures: an undeclared new consumer, an invented requirement reason,
coexisting old/new routes, an unused dependency and a no-op cache ignoring new
inputs. Each seed fails for its intended reason. Authored controls do not count
as hosted participant results.

The shared trajectory demonstrates valid structural variation: an evolved
candidate preserves a focused retained-event owner used by the recorder, while
the direct candidate keeps storage and subscription delivery in one runtime
closure. Both remove the preview strategy. Equality of source text or line count
is not an acceptance criterion.

## Cost and limits

The native delegation interface does not return per-run token counts, a model
identifier, cash cost or an enforceable token cap. No token totals or percentage
quota claims are inferred. The explicit controls are the assigned repository
and task, ten-minute participant ceilings, a fixed initial six-run campaign and
the two affected-case repairs. Deterministic runtime and oracle model calls are
zero. Trial repositories and publication records remain in the user-local
Projector evaluation directory for inspection.

These are bounded observations in a coupled evaluation world. They establish
the tested cleanup, ownership, recovery and no-op outcomes, not universal
semantic correctness, globally minimal architecture, or economic superiority
on a large application.
