# Specification Resolution Ledger

The authoritative specification remains governing. These are the smallest safety-preserving implementation resolutions for seams where two required behaviors cannot otherwise be represented or executed deterministically. They do not redefine product semantics.

1. **Canonical document envelope.** Persist a versioned envelope containing `apiVersion`, `schemaVersion`, `kind`, stable `id`, canonical key, lifecycle, the exact entity payload, semantic/discovery hashes where applicable, and canonical-document hash. Domain payload schemas remain the normative interfaces. This supplies fields required by `canonical-state.md` but absent from individual payloads.
2. **Semantic projections.** The schema registry declares versioned semantic, discovery, volatile, and exact-document field projections per canonical kind. Hashing rejects a kind without a registered projection instead of guessing.
3. **Canonical JSON.** Use recursively key-sorted JSON, UTF-8, finite JSON numbers, omitted `undefined`, rejected duplicate keys/non-JSON values, and domain-separated length-framed hash payloads. `ContentHash` validation requires 64 lowercase hex characters after `sha256:v1:`.
4. **Lineage/tombstone rebuild closure.** Persist lineage and tombstones as independently addressable canonical model records under `.projector/model/lineage/` and `.projector/model/tombstones/`. They are required identity history, not disposable observation.
5. **Cross-domain type ownership.** Types referenced by public kernel contracts physically live in `core`, even when their normative prose is owned by later spec chapters. This preserves `core -> no workspace dependency`.
6. **Impact Closure provenance.** Keep the normative `ImpactClosureRef` exact. Store a content-addressed internal Impact Closure artifact containing per-entry reason, proof class, observability, frontier, and `StateBinding`; the ref hash addresses it.
7. **Transform metadata.** Keep the normative `Transform` and `TransformBinding` exact. Register implementations in an internal declarative `RegisteredTransform` wrapper carrying preconditions, write scope, predecessors, exclusions, commutativity, postconditions, and convergence strategy.
8. **Representation content.** Keep normative projection DTOs exact. Rendered content is addressed by `outputHash` through a host-neutral `RepresentationArtifactStore` port; persisted projections never treat the rendering as authority.
9. **Certificate recovery evidence.** Keep the normative receipt/certificate contracts exact. A versioned certificate evidence artifact, addressed from certificate evidence/unknown fields, records outcome, last checkpoint, journal phase, recovery state, coverage snapshot, lane assumptions, and analyzer failures. Applied/failed/partial execution always emits a certificate; a receipt omits `certificateHash` only during the journal phase before certificate finalization and is not committable in that state.
10. **Reconciliation termination.** Stop only when no material governed state changed **and** every declared fixed-point group is terminal/converged. A non-consecutive repeated digest, iteration exhaustion, or recurring repair emits non-convergence. Volatile run/report/timestamp fields are excluded from the governed-state digest.
11. **Planning Surprise mapping.** `analysis deficiency` maps to `missing-predicted-impact`; `benign incidental mutation` maps to `incidental-change`. The original predicted closure is immutable.
12. **Behavior delta invariants.** Public DTOs remain exact, while Zod `superRefine` enforces kind-specific presence/absence rules for existing IDs and proposed values.
13. **Rule hardness and specificity.** A rule is blocking when its normalized `require`, `forbid`, `restrict`, or required-`validate` product can deny planning/mutation. Specificity is a deterministic tuple of selector constraints and explicitly exact semantic predicates; ties fall back to authority ordering and stable rule ID, never evaluation order. Ambiguous overlapping hard products remain conflicts.
14. **Regex determinism.** Serialized regex selector atoms use a non-backtracking, versioned safe-regex evaluator with deterministic input/step limits. Unsupported expressions fail closed with an explicit selector error; wall-clock timeout never decides semantics.
15. **Ignore policy.** Each ignore list is an exclusion selector list for its named concern. Empty means no exclusions. Matching is union-within-list; the six concerns are independent and never imply one another.
16. **Blocking concern deferral.** An explicit, approved deferral with guardrails and a review trigger is a disposition, not disappearance. The parent concern selector defines affected scope unless the guardrail uses a narrower selector. Govern/Autonomous remains blocked when current safety depends on an unresolved unapproved choice.
17. **Decision/lens endogenous authority.** A lens cannot cite itself as its governance basis. Decision-derived rules retain the decision’s approved-user-intent or harder underlying basis for precedence; a preference never raises that authority.
18. **Slice naming.** “Mandatory first vertical slice” means the first product wedge (delivery Slice 1); Slice 0 is its required correctness substrate.
19. **One-package release.** Internal workspace packages bundle behind the published CLI package. The package graph is an implementation boundary, not a multi-install user requirement.
20. **Non-threshold metrics.** Track all mandated metrics. The 17 explicit gates are blocking; a metric without a normative threshold is reported and cannot be silently converted into a pass/fail threshold.
