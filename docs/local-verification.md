# Local push verification

Run `pnpm hooks:install` once in each clone. The installer uses Git's effective hooks directory, preserves an existing `pre-push` as `pre-push.projector-original`, and chains that hook with the original arguments and stdin through `git hook run`. It does not change `core.hooksPath` or other hooks. An existing backup causes installation to fail rather than overwrite it. A shared hooks directory outside the repository and its common Git directory is rejected. Node, the repository's pnpm version, and Git with `hook run --allow-unknown-hook-name --to-stdin` must be available locally.

On Windows, installation sets `core.longpaths=true` in this repository's local Git configuration, including when the hook is already installed. Every disposable verification clone gets the same local setting automatically. Global Git configuration is unchanged.

On push, the hook reads Git's advertised local and remote object identities. It checks every distinct non-deletion commit in a disposable local clone. This prevents staged, unstaged, and untracked checkout files from substituting for pushed content. It leaves the original index and refs unchanged. Annotated tags are checked at their referenced commit; non-commit objects are rejected.

Every checked commit gets a frozen dependency install and build. A nonempty change consisting entirely of Markdown files under `docs/` runs `spec:check`. All other populations, including missing remote bases, new refs, empty differences, executable files, tests, instructions, configuration, schemas, and release inputs, run `verify` and `release:check`. Multiple refs combine conservatively per commit. There is no approval cache.

The hook compares the destination refs with the advertisement before and after checks. Ref movement or a failed read blocks the push and requires a fresh push attempt. Git still applies its own ref update rules after the hook; this hook cannot lock a remote between its final read and the update. Deletions check the advertised basis but do not run code checks. An empty stream has no proposed updates.

Each command must exit successfully. The hook and installed release check do not impose command completion deadlines; legitimate repository work can finish unless the caller cancels it or a command fails. A check that explicitly requests its own time bound still fails when that bound is exceeded. The hook reports elapsed time for each completed push gate, setup, checkout, install, build, verification, and release check stage. It streams check output into the retained log under `.temp/local-pre-push/` without a total output limit or an in-memory copy. Short Git queries still capture the output needed to validate refs and choose checks. Structured stage records are in the same log. Failed checks block the push. If process cleanup is uncertain, the temporary checkout is retained and its location appears in the error. Reinstall after moving the repository or Node executable. To uninstall, remove the installed `pre-push` and restore `pre-push.projector-original` if present.

These gates run on the pushing machine. They do not establish qualification on another operating system. As with ordinary client-side Git hooks, an explicit `--no-verify` can bypass them; this is not a remote enforcement mechanism.

Projector's disposable observation, query and context caches are stored outside the checkout. The default Windows owner is `%LOCALAPPDATA%/Projector/cache`; macOS uses `~/Library/Caches/Projector`, and other platforms use `$XDG_CACHE_HOME/projector` or `~/.cache/projector`. `PROJECTOR_CACHE_DIRECTORY` can select an absolute host-owned cache directory. Physical checkout identity separates independent clones and replaced directories. Deleting this cache requires a new observation; it does not delete accepted meaning, mutation approval or durable execution evidence.

Git supplies committed trees, index membership, history and ignore rules. Warm exact-source reuse additionally requires a complete host change feed. An optional existing Watchman daemon can supply that feed through `PROJECTOR_WATCHMAN_EXECUTABLE` (an absolute executable path) and `PROJECTOR_WATCHMAN_SOCKET`. Projector starts bounded clients with daemon spawning and local fallback disabled. The daemon's effective exclusions must cover the observation boundary, and Git metadata directories need complete coverage too. Missing configuration uses a bounded rebuild. A lost cursor, changed exclusions or incompatible analysis contract cannot produce a cached current-success result.

Source discovery and both initial and final change-notification checks apply Git's effective repository exclusions. Ignored, untracked build output and log churn do not enter the source graph or invalidate a completed source observation. Tracked files remain included, as in Git, even when an ignore pattern matches them. Ignore rules and other observation-control inputs remain dependencies: changing a rule can expose a new source population and require discovery. Explicitly addressed canonical meaning, local lifecycle evidence and installed producer dependencies use their own storage and verification contracts; source ignore rules do not make those required reads disappear. Git errors are reported and never treated as an empty ignored population.

The current incremental path covers unchanged state, ordinary source edits, additions and deletions in enrolled directories, active-rule membership/cardinality, and supported index or ancestry-preserving Git changes. Directory-population changes, divergent history, move inference, canonical configuration changes and unsupported global analysis require explicit rediscovery. An unchanged warm context does not construct a full planning-impact snapshot. Historical planning evidence keeps its own stronger input contract.

Protocol reference: [Git pre-push documentation](https://git-scm.com/docs/githooks#_pre_push).
