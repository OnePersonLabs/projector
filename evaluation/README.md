# Coupled clean-evolution evaluation

`createTrial(directory, trajectory, mode)` creates a committed JS ESM fixture and returns its root and participant brief. The directory must be empty. Trajectories are `preview`, `shared`, and `ownership`; modes are `evolved` and `direct`. A participant receives only its trial repository, legitimate requirements and brief. Keep this evaluator and its assertions outside participant context.

Set `PROJECTOR_EVAL_RUNTIME` to the installed `dist/change/index.js` entry before launching participants. The generated `scripts/projector.js` adapter invokes production prepare, plan, apply, evidence and revise operations. Nested live OpenSpec specifications, design decisions and active deltas are supplied. The participant implements inside Projector's returned candidate, leaving the original root available to the adapter.

Evolved trials begin with a functional preview strategy and retained event/evidence owner. Their first prospective target adds a preview audit count. `advance` executes that intermediate behavior check, records actual Projector evidence, seals an inspectable Git checkpoint without moving the guarded candidate branch, and revises the same active target to withdraw preview-specific structure and support the late recorder. The final participant stops ready for an actual independent review; the caller records that review and performs finish and the repeated-finish no-op check. Direct trials start with the same final intended target.

After the participant finishes, call `evaluateTrial(originalRoot, trajectory)`. It follows the production candidate identity and requires current Projector plan/evidence plus the evolved checkpoint and distinct target revisions. It returns `passed`, structured `findings`, executed `checks`, and a behavioral trace. `comparePair(evolvedRoot, directRoot, trajectory)` requires both candidates to pass and their observed behavior to agree. Internal source equality is not required.

The world couples playback, provenance, retained evidence, and late recording consumers. The evaluator independently inventories source artifacts, uses the production document extractor/module resolver to trace reachable modules, checks current requirement ownership and withdrawn structure, and exercises the runtime in a bounded subprocess. It then verifies settled reconciliation and introduces a legitimate new consumer to challenge stale cached no-op results. Injected inputs are restored afterward. Each probe subprocess is limited to 15 seconds and 1 MiB of output; each trial is limited to 200 files with a 1 MiB per-file hashing budget.

Run `node --test test/evolution*.test.ts` to qualify the oracle against authored controls and five seeded bad candidates and exercise the production staged adapter. `qualification.ts` is solely an oracle control generator. Its tests explicitly use `authoredControl: true` to isolate oracle behavior from hosted lifecycle evidence. Passing authored controls is not hosted implementation evidence. The seeded failures cover an undeclared consumer, an invented requirement reason, coexisting retired/current routes, an unnecessary dependency, and a no-op cache that ignores changed consumer inputs.

Hosted evaluation consists of exactly three evolved/direct pairs under the configured native host model, with bounded task/context/time limits. The caller records actual host usage where available; this code performs no model calls. The fixture's derived ownership manifest is an evaluation observable, not Projector production state. Installed lifecycle qualification is a separate integration test. These bounded checks do not establish exhaustive semantic correctness, universal architectural minimality, or general performance superiority.
