# Complete Projector readiness

## Why

Projector must make a real Psychord rebuild explainable and verifiable without forcing a second workflow into every task list. Mandatory candidate worktrees, raw task-byte evidence invalidation, candidate-only finish, and TypeScript-only ownership currently obstruct that goal. Parser-only support would leave native, style, configuration, asset, and generated contributions unexplained.

## What Changes

- Restore artifact roles and move shared test-first, impact-aware verification into the verify skill.
- Upgrade exact prior stock schema files while preserving custom templates.
- Default implementation to the selected checkout; retain optional isolation and partial-work recovery.
- Integrate reviewed code, accepted authority, and archive together through hook-respecting recoverable publication that preserves unrelated staging and working edits.
- Separate check freshness from task bookkeeping and review reconciliation, preserving failed and superseded evidence as history.
- Add composed built-in document providers with useful repository resolution for C#, Rust, and Python, domain-specific HTML/CSS/SCSS facts, and Tauri/React Native supplements.
- Inventory binary and large assets without UTF-8 decoding or text-parser-size rejection. Account for retired and generated artifacts explicitly.
- Qualify the installed workflow and realistic Psychord boundaries, including deliberate incomplete and unjustified candidates.

## Capabilities

### Modified

- `projector/workflow`: artifact roles, stock upgrades, shared verification, and integrated completion.
- `projector/changes`: selected-checkout implementation, versioned evidence, contribution disposition, and publication recovery.
- `projector/documents`: provider composition, language resolution, domain addresses, artifact metadata, and explicit semantic limits.
- `projector/observation`: managed checkout enrollment, parser/cache identity, and bounded long-check transport.

## Impact

Changes affect lifecycle state, host transport, kernel enrollment, worker inventory/cache, document extraction/resolution, installed skills/schema resources, and their tests. Existing isolated sessions remain isolated. Existing code/spec/design references and synchronous extraction remain compatible. New language intelligence uses the asynchronous provider service. `.sass` semantic extraction remains explicitly unknown. No dynamic provider installation, custom parser, new impact engine, mandatory per-slice reviewer, or application annotation system is introduced.

The rebuilt Psychord specifications are the workload authority; the previous application is implementation reference. Browser or mock tests cannot establish native audio behavior. Repository publication journals recover interrupted file installation rather than claiming a filesystem-wide atomic update.
