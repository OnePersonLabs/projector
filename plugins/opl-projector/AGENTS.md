# Projector consumer guidance

Use Projector only while this project's `.projector/active` file exists. Check the marker before Projector work, including after a disable request in the same session. A nested Git repository needs its own activation. In an inactive project, carry out the user's request through the native host without Projector records or helpers.

The user describes ordinary work. Select the relevant skill yourself.

- `$opl-projector:recover-meaning` covers unfamiliar meaning or interrupted work.
- `$opl-projector:carry-out-directive` covers implementation.
- `$opl-projector:reconcile-and-learn` covers consequential decisions raised in discussion, planning, or work, and changed evidence or reusable lessons.
- `$opl-projector:enable-projector` covers explicit enable, disable, or activation-status requests.

Do not make the user remember this routing or runtime commands.

Projector preserves meaning and reasons as implementations change. Concepts hold conditions and exceptions; typed Relations explain connections; Projection Units locate implementations. Lenses select participants and collect scoped evidence. Pattern Candidates retain useful approaches and counterexamples. Read the governing meaning, including its prose, before choosing consequential edits. Summaries and source patterns do not replace authority.

Before consequential planning or choosing next work, recover the original user decisions and later corrections that govern it. Start from existing source indexes and linked evidence. Read surrounding replies when needed to distinguish adoption from proposals. Apply accepted priorities, prerequisites, and sequencing. Reuse source-anchored checks while their governing decisions remain current. Limit history retrieval to messages and evidence that can change the decision.

Preserve accepted capabilities, reasons, conditions, and exceptions. Account for substantive changes from the accepted baseline. Resolve material intent gaps or conflicts before dependent work.

Use native execution and delegation. The root owns shared meaning, Lens maintenance, and current task state unless it assigns an exact surface. Give workers disjoint writes, the governing conditions, changed contract, affected consumers, and required evidence. Projector helpers do not schedule agents or execute a second workflow.

In an activated Git project, use reviewable local commits by default, subject to the user's and repository's commit rules. The native root owns staging and commits. Use the commit procedure in `$opl-projector:carry-out-directive`; the user does not need to request each commit. Pushes and history changes need separate authorization.

Before accepting a consequential design, connect each changed rule to its owner, affected consumers, relevant state transitions, and evidence. Include unchanged consumers and recovery paths when the changed rule affects them. Use the selected skill and its application reference. Finish the behavior through its real consumer; a file list or participant check does not establish the complete outcome.

Maintain affected Lenses with the implementation. Compare actual participants with selectors, verify globs against the source tree, and refresh affected bindings and check coverage. Selection is navigation; a Lens with no checks supplies no behavioral support. Keep missing evidence unresolved. Repeated symptom repairs require reassessing the responsible premise before more dependent patches.

Human comprehension is an acceptance requirement. Make behavior, reasons, state changes, and failure paths understandable through code structure and local explanations. If the user cannot follow the result, correct that defect before adding dependent complexity. Mapping files to meaning does not establish comprehensibility.

Update accepted meaning when a decision changes it. Record the decision and its reasons in the owning Concept or typed Relation before dependent implementation or handoff. Preserve proposals, observations, and accepted decisions as distinct. Use `$opl-projector:reconcile-and-learn` for discussion-only changes.

When host mode or write permissions block an update, including Plan mode, use the unsaved-decision handoff. Do not claim it was saved. Keep current task state concise and link retained evidence; replace superseded status instead of appending a diary. Use Git to identify committed source. Extra snapshots or hash inventories need a concrete consumer and decision. A hash establishes byte identity, not correctness or user intent. Preserve original mismatches and unresolved recovery evidence.

Recover only decision-relevant meaning. Select helpers when they reduce a specific uncertainty or repeated task. Batch checks at useful integration points and reuse applicable results. Follow native review rules; a commit does not require another review cycle. Routine work needs no new Projector artifact or global audit. If a mechanism adds cost without useful decisions, suspend it and reassess it against ordinary Git and focused notes.

See [the reference guide](references/guide.md) when YAML, helper requests, provider setup, or repair is needed. Use the selected skill for its workflow.
