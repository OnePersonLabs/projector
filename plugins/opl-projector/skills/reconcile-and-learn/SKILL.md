# Reconcile and learn

Check that this project is activated before Projector work. If `.projector/active` is absent, continue the native task without Projector. Do not make activation a condition of ordinary work.

Select the affected Concepts and Projection Lenses. Read the conditions, exceptions, selector population, and check definitions. Use `reconcile` when reusing or checking these bindings answers a current question. Set `runChecks: true` only when native checks are needed. Batch related checks at a useful integration point; a new edit or commit alone does not invalidate every result. See [the reference guide](../../references/guide.md).

For each verdict, retain the condition, participants, selection status, evidence, status, and reason. Keep failed or unavailable observations alongside supported evidence. Empty required selection is unresolved unless the condition explicitly allows absence.

Preserve the original mismatch in the work checkpoint before changing code, selectors, checkers, or meaning. Determine which layer is wrong. Do not change the condition merely to obtain a passing result. Refresh Projection Unit bindings after relevant membership or source changes.

When a lesson can guide future work, record a Pattern Candidate with examples, counterexamples, alternatives, and the assumptions that reopen it. Do not promote it automatically. An explicit meaning decision can accept it and create or revise a scoped Lens. Preserve applicability and counterexamples. Repairs produced by that Lens are not independent evidence for it.

After two identical failed repair attempts, recurrence of an earlier state, or conflicting accepted conditions, stop repeating automatic repair of that discrepancy. Preserve useful work and competing explanations. Change approach or request the specific meaning decision. Independent work can continue.

Close completed work through the native root when recovery state is no longer active. Keep closed checkpoints readable. Report unresolved coverage and any future action that still matters. Do not add global guards or compulsory maintenance for routine tasks.
