# Reconcile and learn

Check that this project is activated before Projector work. If `.projector/active` is absent, continue the native task without Projector. Do not make activation a condition of ordinary work.

Select the affected Concepts and Lenses. Read governing prose, conditions, exceptions, selectors, and check definitions. Compare actual effects with the intended behavior and pre-change account. Follow [Applying Projector](../../references/applying-projector.md#compare-results-and-reassess-the-premise) to identify missing consumers or a faulty premise. Maintain affected Lens membership and evidence declarations through their assigned owner.

Use `reconcile` when reusing or checking these bindings answers a current question. Set `runChecks: true` only when native checks are needed. Batch related checks at a useful integration point; a new edit or commit alone does not invalidate every result. See [the reference guide](../../references/guide.md) for helper requests and receipt limits.

For each verdict, retain the condition, participants, selection status, evidence, status, and reason. Keep failed or unavailable observations alongside supported evidence. Empty required selection is unresolved unless the condition explicitly allows absence. A Lens with no checks supplies navigation, not behavioral support. Account separately for relevant prose obligations and native evidence outside helper receipts.

Preserve the original mismatch in the work checkpoint before changing code, selectors, checkers, or meaning. Determine whether the defect is in the realization, selection/binding, observation/check, or accepted meaning. Repair the responsible layer. Do not narrow a selector to hide a failure or change a condition merely to obtain a pass. Refresh affected Unit bindings and evidence applicability; preserve independently valid work.

When a discovery changes where future work should look, update the existing Lens, Relation, or Concept that owns it. Preserve observed versus accepted status. When a reusable approach can guide future work, record a Pattern Candidate with examples, counterexamples, alternatives, and reopening assumptions. Do not promote it automatically. An explicit meaning decision can accept it and create or revise a scoped Lens. Preserve applicability and counterexamples. Repairs produced by that Lens are not independent evidence for it.

After two identical failed repair attempts, recurrence of an earlier state, or conflicting accepted conditions, stop repeating automatic repair of that discrepancy. Preserve useful work and competing explanations. Change approach or request the specific meaning decision. Independent work can continue.

Manual patches can expose the same faulty premise through different symptoms. When that happens, pause dependent repairs, trace the responsible rule through its consumers, and revise the connected design before continuing. Do not wait for identical patches or add a new repair counter. Preserve the original mismatch and useful completed work.

Close completed work through the native root when recovery state is no longer active. Keep closed checkpoints readable. Report unresolved coverage and any future action that still matters. Do not add global guards or compulsory maintenance for routine tasks.
