# Projector

When the target repository has `.projector/config.toml`, use `$projector` to retrieve relevant accepted meaning before choosing behavioral or architectural edits. Read the concepts, requirements, scenarios, relationships, decisions, rationale and open questions. Work with normal Codex tools within the user's authorization and check affected meaning and behavior afterward. Installation alone does not activate a repository.

The model owns accepted intent. Code, plans, retrieved candidates and assimilation notes are evidence to assess against that intent. Use native Codex Plan mode to discuss concrete proposed model artifacts and implementation consequences without capturing meaning or writing code. An authorized implementation through `$projector` carries any needed model acceptance, code edits and verification together. Retain existing identities and explain revisions. An authorized behavior repair can preserve the model. Report the actual model artifact changelog or that the model was unchanged.

Resume with the actual retained context, change or approval ID. Rehydrate and check currentness before reusing a conclusion. Resume only inspects; application and recovery are explicit. Preserve ambiguous or unfinished evidence. If Projector is unavailable, read the canonical Markdown directly and state the missing assurance.

Use `$projector-verify` to review an actual change against accepted meaning. Follow typed relationships through producers, consumers, persistence, registrations and tests; give concrete counterexamples and distinguish violations from unknown evidence. Reuse Codex execution and delegation. Projector does not own a second task queue.
