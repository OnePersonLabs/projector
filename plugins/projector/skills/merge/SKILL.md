---
name: merge
description: Integrate a pinned source commit through isolated merge construction, independent review, and recoverable publication that preserves unrelated local work.
---

Read [the runtime contract](../apply/references/runtime.md) and [conflict review and recovery](references/conflict-review.md) when conflicts or interrupted publication occur.

1. Resolve the source repository and branch from the request. Select an explicitly named ref or one unambiguous relevant published result. Pin the source commit and original target branch/HEAD. Do not fetch a moving remote unless requested. Refuse an unborn or detached target and an active merge/rebase/cherry-pick/revert.
2. Inventory staged, unstaged, and untracked target changes separately, retaining exact bytes and index identity. Unrelated dirty work is permitted. Never stash, reset, commit unrelated changes, or require a clean checkout merely for convenience. If the source is already an ancestor, report a verified no-op. Unrelated histories need an explicit issue-specific decision after investigation.
3. Create a unique temporary detached linked worktree at the pinned target. Use a Git-ignored worktree directory or an external temporary directory. Record target branch/HEAD, source commit, and worktree. Construct `git merge --no-ff --no-commit --no-autostash --no-rerere-autoupdate --no-overwrite-ignore` there with the pinned source. Do not attach the target branch to that worktree.
4. Inspect the complete merge, including cleanly merged files. For conflicts inspect merge base, both stages, callers, requirements, designs, tests, and history. Resolve only when evidence establishes one coherent result. Never select a side because it is newer or larger. Preserve the original target while unresolved. Finish independent investigation before presenting a self-contained brief for remaining choices.
5. Check the staged merge, then create its commit with normal identity, signing, configuration, and hooks. Inspect the actual resulting commit and hook writes. The pinned source must be a parent. Resolve hook changes before qualification; do not claim pre-hook evidence covers changed inputs.
6. Use $projector:verify on the complete target-to-integration difference. Run applicable checks and obtain real independent adversarial review of commits, diff, conflicts, checks, unsupported retained artifacts, and the strongest simpler alternative. Apply justified corrections in the temporary worktree and refresh affected evidence/review. If review or checks remain unresolved, preserve the worktree and report the precise blocker.
7. Load `preparePublication` and `publishPublication` from the installed runtime's `dist/change/index.js` using the configured Node runtime. Call `preparePublication({root,targetBranch,targetHead,commit,directory})`, with the pinned original target and exact reviewed commit in the temporary detached linked worktree. This prepares residual user staging and working changes, including disjoint edits within the same file. Actual overlaps or target drift remain explicit conflicts; never implement a second ref/index publication algorithm in the skill.
8. Call `publishPublication(root,transaction)` to journal conditional branch advancement and recoverable checkout/index installation. Keep the returned transaction and journal location. After interruption, inspect that journal and resume the same transaction; preserve unexpected edits. Do not repin or force-update a moved target.
9. Verify target tree, preserved user changes, and source ancestry after settled publication. Remove only the exact temporary worktree after successful installation. An atomic reviewed commit and recoverable file installation do not imply a filesystem-wide atomic transaction.

Completion: the target contains the pinned source through a reviewed integration, unrelated work survives, and temporary integration is removed. A verified no-op or reviewed deliberate rejection also completes. Otherwise retain recoverable work and report one precise remaining obligation.
