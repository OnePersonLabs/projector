---
name: merge
description: Merge a selected source branch into the current working branch with isolated conflict resolution, checks, adversarial review and human escalation.
---

Read [conflict review and recovery](references/conflict-review.md) when a conflict occurs, a human decision is required, or an interrupted integration must resume.

1. Resolve the source repository and source branch from the request. Use an explicitly named ref. Otherwise, select one unambiguous relevant published candidate or ask after inspecting available branches. Pin the source commit. Do not fetch or substitute a moving remote ref unless the user requested that network update.
2. Capture the original working directory, its attached target branch and exact target commit. Require no merge, rebase, cherry-pick or revert in progress. Require a clean index and worktree, including untracked files. Do not stash, commit or discard local work for the user.
3. If the source commit is already an ancestor of the target, report a verified no-op. Refuse an unborn or detached target. Refuse unrelated histories unless the user explicitly authorizes that specific merge after seeing its consequences.
4. Create a unique temporary `projector/merge-*` branch at the pinned target. Use `.worktrees/` only when `git check-ignore` confirms that Git ignores the directory. Otherwise, use an external temporary directory. Check out the temporary branch in a locked linked worktree at that location. Record the original target branch, target commit, pinned source commit, temporary branch and worktree path in the conversation. Do not attach the target branch to the temporary worktree.
5. In the temporary worktree, run `git merge --no-ff --no-commit --no-autostash --no-rerere-autoupdate --no-overwrite-ignore` with the pinned source commit. Pass refs as command arguments and terminate option parsing where the Git command supports it. Do not bypass hooks or signature requirements.
6. Inspect the complete merge, including cleanly merged files. For each conflict, inspect the merge base, target stage, source stage, surrounding callers, requirements, designs, tests and relevant history. Resolve it only when that evidence establishes one coherent result. Never select a side because it is newer, larger or from the source branch.
7. Resolve every supported conflict and run the cheapest discriminating checks. If uncertainty remains, finish all independent investigation and supported resolutions first. Then preserve the locked worktree and present one self-contained human decision brief for all unresolved conflicts. The original target must remain unchanged.
8. When the index has no unmerged entry, inspect the staged merge, run `git diff --cached --check`, and create the merge commit without bypassing hooks. Use a message that names the source ref and target branch. The pinned source commit must be a parent of this commit.
9. Run the applicable repository checks against the complete target-to-integration diff. Obtain a genuinely independent adversarial review through a native subagent or separate reviewer environment. Supply the pinned commits, actual diff, conflict resolutions and check results. Ask the reviewer to find missing concerns, unsafe retained behavior, counterexamples and the strongest simpler alternative. If independent review is unavailable, preserve the integration and report the blocker.
10. Apply supported fixes or partial reversions in separate commits on the temporary branch. Rerun affected checks and obtain a fresh review of material fixes. If review supports rejecting the whole source branch, confirm that the target is unchanged and the temporary branch still points to the reviewed integration commit. If either ref moved, preserve the worktree and report the drift. Otherwise, unlock and remove the exact temporary worktree, then force-delete only the exact temporary branch with `git branch -D`. Report that the target was intentionally left unchanged.
11. Before publication, verify that the original working directory is on the same target branch at the pinned target commit. Verify that it remains clean and has no Git operation in progress. If any check fails, preserve the temporary integration and report the exact drift. Do not rebase, repin or merge into the moved target automatically.
12. Run the final affected checks in the temporary worktree. After they pass, verify that its branch and HEAD still identify the reviewed integration commit. Verify that its index and worktree are clean, including untracked but not ignored files. Then repeat the branch, exact target commit, clean-state and inactive-operation checks in the original working directory immediately before publication. Publish with `git merge --ff-only --no-overwrite-ignore` and the reviewed temporary branch. Verify that the target tree equals the checked integration tree and that the resulting commit graph contains the pinned source parent. Only after success, unlock and remove the linked worktree and delete the temporary branch with ordinary Git worktree and branch commands.

Completion: the original target contains the pinned source through a reviewed merge and no temporary integration remains. A verified no-op or deliberate full rejection also completes the operation. Otherwise, preserve the temporary integration and report one actionable blocker with a self-contained decision brief.
