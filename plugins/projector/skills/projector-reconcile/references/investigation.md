# Delegated investigation

Read this after user authorization or when assigned the subagent role. Use the installed [operation contract](../../projector/operation-contract.md); exact registered schemas own requests.

## Establish the comparison

Start from the assigned finding, its from/to commits, bounded paths, omitted counts, and evidence identity. Inspect the local diff and affected area. A baseline hash does not retain old uncommitted file contents; state that limit when those bytes are unavailable. Do not fetch, pull, switch branches, or reconstruct missing intent by guessing.

If a saved context ID exists for the work, send `reconcile` with that ID. Compare its recorded reasoning dependencies with current evidence. Separate stale knowledge from violated predicates and missing observations. Refresh affected context before relying on stale conclusions. Do not choose an arbitrary latest context and pretend it represents this work.

Without relevant saved reasoning, retrieve `context` for the changed area's apparent outcome and inspect current accepted intentions. State explicitly that files alone cannot recover historical intent. Use scoped `cleanup` only for a concrete missing comparison or unfinished lifecycle: it inspects and proposes continuation; it does not repair files. Respect disclosure counts and remaining frontiers.

Inspect the current implementation and tests needed to distinguish realization of existing meaning, proposed meaning, contradiction, and uncertainty. Preserve alternate conforming implementations. Assimilation topic notes remain candidate source synthesis, independent from Projector concept records.

## Resolve only what evidence and authorization permit

When a material choice remains, send the root one self-contained question, two or three mutually exclusive options, a recommendation, and the work dependent on it. Continue independent inspection; retain unanswered questions. Do not invoke `request_user_input` from the subagent.

Report proposed repair with its reason and affected scope. Prefer applicable existing repair and regeneration routes. Use `$projector-change` when intended canonical meaning changes; never infer authorization for that change from repeated code, file mappings, or a hook finding. Coordinate with the root before writes, including writes to shared design records.

Keep inspection outputs in their existing Projector runtime owners. If a durable narrative is needed, use `.projector/runtime/repository-check/investigations/` with a finding-specific Markdown file; do not create a second workflow or accepted-model store. Return at most a short summary plus evidence references, questions, and the inspected finding/evidence identity.

## Hand back current evidence

Recheck the finding before delivery. If the repository changed during analysis, refresh affected reasoning or report the remaining uncertainty; do not mark a newer finding handled using an older report. Persist unanswered material questions and the next investigation step in the finding-specific runtime note, and tell the root to keep that finding pending. The root uses `repository.check` with `handled: { findingId, evidenceIdentity }` only for the exact completed investigation or explicitly dismissed finding, never for an interim report awaiting an answer. That operation verifies a full current observation before acknowledgement. Unrelated unresolved design work remains in its existing owner.
