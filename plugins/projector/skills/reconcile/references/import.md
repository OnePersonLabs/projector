# Import selected uncommitted implementation safely

1. Resolve repository HEAD and capture source status plus separate cached/uncached diffs. Set `GIT_OPTIONAL_LOCKS=0` for inspection commands so Git does not refresh the source index as an incidental write. Use porcelain v1 with NUL separators for filenames, `git diff --cached --binary`, `git diff --binary`, and `git ls-files --others --exclude-standard -z`. Read untracked content and inspect renames, deletions, binary files, and submodule changes explicitly. Capture source index bytes and selected/excluded file content hashes for preservation checks.
2. Classify one coherent patch. Record included paths/hunks, final expected bytes or deletion, baseline identity, and excluded/ambiguous work. If unrelated edits share a file, construct a selected hunk patch against HEAD and validate it in the candidate; copying the whole file would import unrelated work.
3. Recheck the source inventory before import. If it changed, recompute affected selections instead of importing a stale snapshot. Do not stage, stash, reset, clean, checkout, format, or rewrite source implementation/index to create the import.
4. Have $projector:propose author the change and prepare a candidate at the same HEAD. Account for added proposal files separately from implementation selection; do not import runtime state or source .git data.
5. For whole selected tracked files, construct a binary-capable selected patch with `git diff --binary HEAD -- PATHS` to the final worktree state, retaining staged-only additions/deletions and unstaged changes. Capture subprocess stdout as bytes and write those bytes to a patch file; avoid PowerShell pipelines that transcode binary content. A temporary patch belongs outside tracked source. For partial-file selection, generate only approved hunks and inspect the resulting diff.
6. Start an acknowledged candidate write batch for all affected paths. Check patch applicability in the candidate before applying. Copy selected untracked files byte-for-byte with parent directories and relevant executable/symlink semantics; preserve selected deletions and renames. If a submodule change or special file cannot be reproduced safely, report that path as blocked instead of silently flattening it.
7. Compare imported candidate diff and selected expected content. Confirm excluded paths remain unchanged and source implementation/index match the pre-import inventory (apart from independently authorized artifact authoring or concurrent user edits). On conflict, leave original work intact and resolve only within the candidate.
8. Call validatePlan with actual imported contribution coverage, reconcile task completion, and run candidate evidence/review. Historical source tests and a visually identical patch do not establish current candidate verification.

Completion reports include selected/excluded paths, selection basis, historical reconstruction provenance, source preservation checks, and actual candidate verification. Do not claim spec-first provenance for work reconstructed afterward.
